# 企画フェーズ

書籍の目次構成、各章のアウトライン、読者の学習パスを設計し、Markdownファイルの骨格を生成する。

## 手順

### 1. ヒアリング

以下の項目をユーザーに確認する:

| 項目 | 説明 |
|------|------|
| テーマ | 書籍が扱う技術領域・主題 |
| 対象読者 | 読者の前提知識・レベル（初心者、中級者、上級者） |
| ゴール | 読者が本書を読み終えた後に達成できること |
| 想定分量 | 大まかなページ数・章数の希望（なければ目安を提案） |
| 演習の有無 | 章末問題、ハンズオン演習、プロジェクト課題等を含めるか |

### 2. 全体構成の設計

以下の観点で目次構成を設計する:

**構成パターン**（書籍の性質に応じて選択）:

| パターン | 特徴 | 適する書籍 |
|---------|------|-----------|
| 段階的導入型 | 基礎→応用→発展と段階的に進む | 入門書、チュートリアル型 |
| リファレンス型 | 機能・トピック別に独立した章 | API解説、設定ガイド |
| プロジェクト型 | 実際のプロジェクトを段階的に構築 | ハンズオン・実践書 |
| 試験対策型 | ドメイン別解説＋模擬試験 | 資格試験対策本 |

**設計の目安**:
- 1章あたり 500〜1500行（Markdown）
- 全体 8〜15章が標準的
- 各章は可能な限り独立して読めるようにする
- 章の前後関係が必要な場合は、依存関係を明示する

### 3. 各章のアウトライン作成

各章について以下を定義する:

```
## 第N章: <章タイトル>

**目的**: この章で読者が学ぶこと
**前提**: 先に読んでおくべき章（あれば）
**想定行数**: NNN行

### N.1 <セクション名>
- 扱う内容の箇条書き

### N.2 <セクション名>
- 扱う内容の箇条書き

### 章末演習（任意）
- 演習問題の概要
```

### 4. 読者の学習パスの確認

- 難易度が段階的に上がっているか
- 前の章の知識が後の章で活用されているか
- 各章の分量バランスが適切か
- 重複する内容がないか

### 5. ユーザーへの提示と承認

設計した目次構成を提示し、ユーザーの承認を得る。フィードバックがあれば修正する。

### 6. Markdownファイルの生成

承認後、`src/` 配下にMarkdownファイルを生成する:

- 各章ファイルにはH1（章タイトル）とH2（セクション見出し）の骨格を含める
- 本文は未記入（後の write フェーズで執筆）

**ファイル生成例**:

```markdown
# 第1章 はじめに

## 1.1 本書の対象読者

## 1.2 本書の構成

## 1.3 開発環境の準備
```

### 7. コミット

```bash
git add src/
git commit -m "✨ 目次構成と章の骨格を追加"
```

注: ビルドスクリプトは `src/` 配下の `.md` ファイルを自動検出するため、`sourceFiles` 配列の手動管理は不要。

### 9. 完了メッセージ

目次構成が完了したことを報告し、次のステップ（`/book-writing write` で各章の執筆）を案内する。各章の執筆順序について推奨がある場合は併せて伝える。
