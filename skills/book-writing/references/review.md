# レビュー＆ビルドフェーズ

書籍全体の品質を検証し、EPUBをビルドする。レビューモードとビルドモードの2つのサブモードを持つ。

## モード判断

- 「レビューして」「品質チェックして」→ レビューモード
- 「ビルドして」「EPUBを生成して」→ ビルドモード
- 「レビューしてビルドして」→ 両方を順番に実行

## レビューモード

### 1. 全章の読み込み

`src/` 配下の全Markdownファイルを読み込み、書籍全体を把握する。

### 2. 章間整合性チェック

以下の観点で全章を横断的に検証する:

#### 用語の統一

- 同じ概念に対して異なる表記が使われていないか
  - 例: 「API キー」vs「APIキー」、「エンドポイント」vs「end point」
- 技術用語の英語併記が初出時に行われているか
- 略語の定義が最初の使用箇所で行われているか

#### 前後参照の正確性

- 「第N章で述べた〜」の N が正しいか
- 「第N章で詳述する」の N が正しいか、かつ実際にその章で説明されているか
- 参照先の内容が実際に記載されているか

#### 内容の重複

- 同じ説明が複数の章で繰り返されていないか
- 重複がある場合、1箇所に集約して他は参照にできるか

#### 難易度の段階性

- 前の章で説明していない概念を前提にしていないか
- 難易度が急激に上がるポイントがないか

### 3. 技術的正確性チェック

- **コード例**: 構文エラーがないか、使用しているAPIが実在するか
- **バージョン情報**: ライブラリやツールのバージョンが現在のものと整合しているか
- **技術的主張**: 「〜が最も高速」「〜が推奨」等の主張に根拠があるか

### 4. 読者体験チェック

- 各章の冒頭に「この章で学ぶこと」の概要があるか
- 各章の末尾に要約や次章への導線があるか
- 説明が不足している箇所がないか（専門用語の未定義使用等）
- コード例の分量が適切か（多すぎず少なすぎず）

### 5. EPUB互換性チェック

全ファイルを走査して以下を検出する:

```bash
# 禁止HTMLタグの検出
grep -rn '<details\|<summary\|<iframe\|<object\|<embed\|<video\|<audio' src/

# 言語指定なしのコードブロックの検出
grep -n '```$' src/*.md

# 見出し階層の飛ばしチェック（H1の直後にH3がないか等）
# → 各ファイルの見出しを抽出して目視確認
grep -n '^#' src/*.md
```

### 6. レビュー結果の報告

発見した問題をカテゴリ別にテーブル形式で報告する:

```markdown
| # | カテゴリ | ファイル | 行 | 問題 | 修正案 |
|---|---------|---------|-----|------|--------|
| 1 | 用語統一 | 03-xxx.md | 42 | 「API キー」→他章では「APIキー」 | 「APIキー」に統一 |
| 2 | 前方参照 | 05-xxx.md | 128 | 「第3章で述べた」が第4章の内容 | 「第4章」に修正 |
| 3 | EPUB互換 | 07-xxx.md | 55 | 言語指定なしコードブロック | ```python を追加 |
```

### 7. 修正の適用

ユーザーの承認を得た後、報告した修正を適用する。修正後に再度ビルドして確認する。

## ビルドモード

### 1. 前提確認

```bash
which pandoc && which deno
```

### 2. 表紙の確認

`assets/cover.png` の存在を確認する:
- **存在する** → そのままビルドに含める
- **存在しない** → `book.yaml` の `cover.provider` が `none` 以外なら、表紙生成スクリプトの実行を提案する:
  ```bash
  deno run --env-file=<プロジェクトルート>/.env --allow-net --allow-read --allow-write --allow-run --allow-env scripts/generate-cover.ts
  ```
- 表紙が不要な場合はスキップしてビルドに進む

### 3. ビルド実行

```bash
deno run --allow-run --allow-read --allow-write scripts/build.ts
```

### 4. 結果報告

- ビルド成功/失敗
- 出力ファイルパス
- ファイルサイズ（MB）
- スキップされたファイル（あれば）

### 5. エラー対応

ビルドが失敗した場合:

| エラー | 原因 | 対処 |
|--------|------|------|
| pandoc: command not found | Pandoc未インストール | `brew install pandoc` |
| Markdown parse error | 不正なMarkdown記法 | エラー行を確認して修正 |
| YAML parse error | book.yaml の構文エラー | YAMLの構文を修正 |
| Permission denied | ファイル権限の問題 | dist/ の権限を確認 |

### 6. コミット（修正があった場合）

```bash
git add -A
git commit -m "👍 品質改善: レビュー指摘事項を修正"
```
