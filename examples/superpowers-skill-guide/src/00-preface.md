# まえがき

## 本書の目的

AIコーディングエージェント（AI Coding Agent）に「あとはよろしく」と任せた結果、テストのないコードが量産されたり、既存のアーキテクチャを無視した実装が生まれたりした経験はないでしょうか。

2025年から2026年にかけて、Claude Code、Cursor、GitHub Copilot、Codex、Gemini CLIといったAIコーディングエージェントが普及し、「AIにコードを書いてもらう」ことは日常になりました。

コンパイラ、IDE、バージョン管理システム——過去の技術革新はいずれも、開発者の生産性を段階的に向上させてきました。しかし、AIエージェントの登場は、それらとは質的に異なる変化です。IDEの自動補完と異なり、AIエージェントは単なる入力支援ではなく、**設計判断を含む複雑なタスクを自律的に実行する存在**です。ファイルの作成、テストの実行、Gitのコミットまで、一連の作業を人間の介入なしに行えます。

この自律性は、新たな課題も生み出しています。自律的に行動するということは、自律的に「間違う」こともあるということです。そして、AIエージェントの「間違い方」は、人間のそれとは性質が異なります。

普及が進むにつれて、**AIエージェントの出力品質にばらつきが大きい**という問題が顕在化してきました。同じタスクを依頼しても、あるときはテスト付きの美しいコードが、あるときはテストなしの場当たり的なコードが生成される。この不安定さが、多くの開発者を悩ませています。

この問題は、単にプロンプトの書き方が悪いというレベルの話ではありません。根本的な原因は、AIエージェントに**ソフトウェアエンジニアリングの規律を与える仕組みが欠けている**ことにあります。

人間のエンジニアは、チームのプロセスや文化、コードレビュー、メンタリングなどを通じて、規律を身につけていきます。「テストを書く」「計画を立てる」「レビューを受ける」——これらのプラクティスは、個人の善意だけでなく、チームの仕組みとして定着しているからこそ機能しています。

AIエージェントにも、同様の**外部からの規律付けの仕組み**が必要です。そして、その仕組みこそがSuperpowersなのです。

本書は、こうした課題に対する実践的な解決策である**Superpowers**スキルフレームワークを、設計思想から活用法まで体系的に解説するものです。

Superpowersは、GitHub上で**119,700以上のスター**を獲得し、**9,700以上のフォーク**が作成されている、AIコーディングエージェント向けスキルフレームワークの決定版です。リポジトリ名は`obra/superpowers`で、作者のJesse Vincent氏（GitHub: obra）によって開発・メンテナンスされています。

Superpowersが提供するのは、単なるプロンプトテンプレートの集合ではありません。テスト駆動開発（Test-Driven Development）、体系的なデバッグ、コードレビューといったソフトウェアエンジニアリングのベストプラクティスを、AIエージェントが確実に実行するための「行動規範」です。

プロンプトテンプレートとスキルフレームワークの違いは何でしょうか。プロンプトテンプレートは「何を出力するか」を指定するものです。一方、Superpowersのスキルは「どのように考え、どのように行動するか」を規定するものです。出力の形式ではなく、プロセスそのものを制御する——ここにSuperpowersの本質があります。

具体的には、Superpowersを導入することで、エージェントの振る舞いが以下のように変わります。

- **実装前に要件を確認するようになる** — 「まず理解してから行動する」習慣が身につく
- **テストを先に書くようになる** — テスト駆動開発が「推奨」ではなく「必須」になる
- **計画を立ててから実装するようになる** — 場当たり的なコード生成が抑制される
- **完了宣言の前に検証を行うようになる** — 「できました」の前に証拠を提示する
- **デバッグを体系的に行うようになる** — 推測ではなく仮説と検証に基づく問題解決

本書は、これらの変化がなぜ起こるのか、どのような仕組みで実現されているのかを、技術的な深さを保ちながらも分かりやすく解説します。

本書を通じて、読者の皆さまがSuperpowersを使いこなし、AIエージェントとの協働をより生産的で信頼性の高いものにできることを願っています。

## 対象読者と前提知識

本書は、以下のような読者を想定しています。

**メインターゲット: AIエージェントを使いこなしたい中級者**

- **Claude Code、Cursor、Codex**などのAIコーディングエージェントを日常的に使用している開発者
- スキル（Skills）やカスタムインストラクション（Custom Instructions）の概念は理解しているが、Superpowersを**体系的に活用したい**中級者
- AIエージェントの出力品質に課題を感じており、**再現性のある改善手法**を求めている方

**サブターゲット: チームへの導入を検討しているリーダー**

- 開発チームにAIエージェントを導入済みだが、品質のばらつきに困っている技術リーダー
- AIエージェントの利用に関するチームガイドラインを策定したいマネージャー
- エージェントの出力品質を定量的に改善したいと考えている品質保証（QA）担当者

### 本書を読んだ後にできるようになること

本書を読み終えた後、読者は以下のことができるようになります。

- Superpowersのすべてのスキルの目的、使い方、効果を理解し、適切な場面で活用できる
- ハードゲート、鉄の掟、合理化防止テーブルの設計原理を理解し、その効果を説明できる
- プロジェクトやチームの状況に応じて、スキルの選択的有効化やカスタマイズを行える
- 独自のカスタムスキルを設計・実装できる
- AIエージェントとの協働における品質課題を構造的に分析し、対策を立てられる

これらの能力は、Superpowersに限らず、AIエージェント全般との協働において価値を持つ汎用的なスキルです。

## 本書の構成

本書は3つのパートで構成されています。各パートは独立性を持たせているため、興味のあるパートから読み始めることも可能です。ただし、パート1の第3章「コアワークフロー」は、パート2以降の理解に不可欠なため、先に読むことを強く推奨します。

### パート1: 基礎（第1章〜第3章）

Superpowersの全体像を理解するためのパートです。「Superpowersとは何か」「どう使い始めるか」「全体の流れはどうなっているか」という基本的な問いに答えます。

- **第1章「Superpowersとは何か」** — AIコーディングエージェントが抱える根本的な課題と、Superpowersがそれをどう解決するかを解説します。4つの設計原則、心理学的アプローチ、作者とコミュニティについても触れます。

- **第2章「インストールとセットアップ」** — Claude Code、Cursor、Gemini CLI、Codex、OpenCodeの各プラットフォームへのインストール手順を説明します。スキルの有効化確認方法、設定のカスタマイズ、チーム共有の方法まで網羅しています。

- **第3章「コアワークフロー」** — Superpowersの中核をなす7段階のワークフローを俯瞰します。スキル間の連携、ハードゲート（HARD-GATE）機構、鉄の掟（Iron Law）パターン、合理化防止テーブルといった重要な設計パターンを学びます。本書全体を理解するための最重要章です。

### パート2: 各スキル詳解（第4章〜第9章）

個々のスキルを深掘りするパートです。各章は独立しているため、必要なスキルから読み始めることができます。

- **第4章「ブレインストーミング」** — 実装前の要件整理と設計探索のスキルを解説します。エージェントが「すぐにコードを書きたがる」問題を抑制し、十分な理解に基づく設計を引き出す方法を学びます。

- **第5章「プランニング」** — 実装計画の立案スキルと、サブエージェント駆動開発（Subagent-Driven Development）スキルを解説します。計画の粒度、テスト方針の組み込み、リスク管理など、実践的なテクニックを紹介します。

- **第6章「テスト駆動開発」** — Superpowersの中で最も重要なスキルであるTDDスキルの詳細を解説します。エージェントにテストファースト（Test-First）を徹底させる仕組み、レッド→グリーン→リファクタのサイクル管理、よくある失敗パターンとその対策を学びます。

- **第7章「デバッグ」** — 体系的デバッグ（Systematic Debugging）スキルの活用法を解説します。「推測でコードを変更するな」の原則に基づく、仮説→検証→記録のデバッグプロセスを詳述します。

- **第8章「コードレビュー」** — レビュー依頼（requesting-code-review）と受領（receiving-code-review）の双方のスキルを解説します。エージェントが自分のコードを客観的にレビューする仕組みと、レビューフィードバックを適切に処理する方法を学びます。

- **第9章「Git操作とブランチ管理」** — Gitワークツリー（Git Worktrees）の活用と、開発ブランチの完了処理（finishing-a-development-branch）を解説します。作業環境の隔離、ブランチの統合方法の選択、後片付けのプロセスを学びます。

### パート3: 応用（第10章〜第11章）

Superpowersをさらに活用するためのパートです。自分だけのスキルを作りたい方、エコシステム全体を理解したい方に向けた内容です。

- **第10章「カスタムスキルの作成」** — 独自のスキルを設計・実装する方法を解説します。Superpowersの`writing-skills`スキルを活用した効率的なスキル開発手法と、効果的なスキルを書くためのベストプラクティスを紹介します。スキルの構成要素（鉄の掟、ハードゲート、合理化防止テーブル）を設計する際の具体的な指針を学びます。

- **第11章「エコシステムと今後の展望」** — Superpowersを取り巻くエコシステムと、AIエージェントスキルの未来について考察します。コミュニティが生み出した注目のスキル、他のフレームワークとの比較、今後の技術動向を俯瞰します。AIエージェントの進化に伴い、スキルフレームワークがどのように変化していくかを展望します。

### 推奨する読み方

**初めてSuperpowersに触れる方**

第1章→第2章→第3章と順に読み進め、まず全体像をつかんでください。その後、第6章（TDD）を読んで実際にSuperpowersの効果を体験することをお勧めします。TDDスキルは、効果を最も即座に実感できるスキルです。

**特定のスキルを深掘りしたい方**

第3章で全体像を確認した上で、興味のあるスキルの章に進んでください。各章は独立性を持たせていますが、第3章で説明するハードゲートや鉄の掟の概念を前提としています。

**チームへの導入を検討している方**

第1章で設計思想を理解し、第2章でセットアップの手順を確認した上で、第10章のカスタムスキル作成と第11章のエコシステムの章を参照してください。チーム導入の際には、まず2〜3名のメンバーで試用し、効果を確認してから全体に展開することを推奨します。

**既にSuperpowersを使用している方**

特定のスキルの理解を深めたい場合は、パート2の該当章を直接読んでください。また、第10章のカスタムスキル作成は、Superpowersをさらに活用するための実践的な知識を提供します。

## 表記上の注意

本書では、以下の表記規則を採用しています。

### 技術用語の表記

技術用語は、初出時に日本語表記の後に英語を括弧で併記します。2回目以降は日本語表記のみを使用します。

例: テスト駆動開発（Test-Driven Development）→ 以降は「テスト駆動開発」

ただし、一般的に英語のまま使用されることが多い用語（Git、GitHub、Markdownなど）は、日本語訳を付けずに英語表記のまま使用します。

### コマンドとコードの表記

コマンドラインの入力は、以下のようにコードブロックで表記します。

```bash
claude /install-skill obra/superpowers
```

コマンドの実行結果を示す場合は、`$`プロンプトに続けて入力を示し、その下に出力を表示します。

```bash
$ claude /skills
Installed Skills:
  obra/superpowers (v5.0.6)
    brainstorming
    test-driven-development
    ...
```

設定ファイルやコードの断片は、言語指定付きのコードブロックで表記します。

```markdown
## HARD-GATE: テストが全件パスするまで次に進まない
```

```python
def test_example():
    assert calculate(2, 3) == 5
```

### スキル名の表記

Superpowersのスキル名は、原文の英語表記をそのまま使用します。これは、実際のコマンド入力時にスキル名を英語で指定する必要があるためです。

例: `brainstorming`、`test-driven-development`、`writing-plans`

本文中でスキルの日本語名に言及する場合は、初出時に英語名を併記します。

例: ブレインストーミング（`brainstorming`）スキル → 以降は「ブレインストーミングスキル」

### 図の表記

本書に含まれる図は、Mermaid記法で記述されています。EPUBリーダーによっては、Mermaidの図が正しく表示されない場合があります。その場合は、図の前後にある説明文を参照してください。

すべての図には、図の前に内容の説明を記載しているため、図が表示されなくても内容の理解に支障はありません。

### 注意書きの表記

本文中の補足情報や注意事項は、以下の形式で表記します。

> **注意**: これは重要な補足情報の例です。見落とすと問題が発生する可能性がある情報を示します。

> **ヒント**: これは役立つヒントの例です。知っておくと便利な情報を示します。

> **コラム**: これは発展的な話題の例です。本筋から少し外れるが、理解を深めるのに役立つ情報を示します。

### エージェントの対話例

エージェントとの対話例を示す場合は、以下の形式を使用します。

```
ユーザー: このプロジェクトに認証機能を追加してください。

エージェント: 認証機能の追加について、いくつか確認させてください。
1. 認証方式はどれを想定していますか？（JWT、セッション、OAuth等）
2. ユーザー登録機能も必要ですか？
3. パスワードリセット機能は必要ですか？
```

この形式で、Superpowersが有効な場合のエージェントの振る舞いを具体的に示します。

### Superpowersの用語

本書では、Superpowers固有の用語を以下のように表記します。

- **ハードゲート**（HARD-GATE）— 条件を満たすまで次に進めない関門
- **鉄の掟**（Iron Law）— 各スキルの最も重要なルールの一文宣言
- **合理化防止テーブル**（Rationalization Prevention Table）— エージェントの言い訳に対する事前反論集
- **横断的スキル**（Cross-cutting Skills）— ワークフローのどの段階でも呼び出されるスキル

これらの用語は、第3章で詳しく解説します。

### プラットフォーム固有の情報

特定のプラットフォームにのみ該当する情報は、プラットフォーム名を明示します。

> **Claude Code固有**: この機能はClaude Codeでのみ利用可能です。

> **Cursor固有**: Cursorでは、この設定はSettings画面から行います。

### Superpowersの原文引用

Superpowersのスキル内容を引用する場合は、コードブロックで囲んで表記します。ただし、スキルの原文は英語で記述されているため、本書では日本語に意訳した内容を掲載しています。原文を確認したい場合は、公式リポジトリのスキルファイルを参照してください。

### 互換性に関する注意

Superpowersのスキルは、基盤となるLLMの能力に依存して動作します。そのため、以下の点にご注意ください。

## 本書の読み方に関する注意

### 「正解」は一つではない

Superpowersは「こうすべき」という強い主張を持つフレームワークですが、それが唯一の正解であるとは限りません。本書で紹介するプラクティスは、多くの開発者にとって効果的であることが実証されていますが、すべてのプロジェクト、すべてのチームに最適とは断言できません。

Superpowersの**設計思想を理解した上で、自分のコンテキストに適応させる**ことが大切です。スキルの内容をそのまま使うのではなく、なぜそのように設計されているかを理解し、必要に応じてカスタマイズしてください。

例えば、プロトタイピングフェーズでは厳格なTDDが必ずしも最適でない場合もあります。また、1行の設定変更に対してフルワークフローを適用することは過剰でしょう。状況に応じた柔軟な適用が、Superpowersを最大限に活用する鍵です。

第3章で紹介する「パターン選択マトリクス」は、タスクの規模とリスクに応じて適切なワークフローパターンを選ぶための指針を提供します。すべてのタスクにフルワークフローを適用する必要はありません。

### 手を動かしながら読む

本書は、実際にSuperpowersをインストールし、使いながら読むことを強く推奨します。各章には具体的なコマンドや設定例が含まれており、手を動かすことで理解が深まります。

特に第3章以降は、実際のプロジェクトでSuperpowersを使いながら読むと、スキルの効果を実感できるでしょう。

### 批判的に読む

本書はSuperpowersの解説書ですが、Superpowersの宣伝書ではありません。各スキルの設計について、その利点だけでなく、限界や適用上の注意点も率直に記述しています。

Superpowersのアプローチが効果的でない場面や、コストに見合わない場面もあるかもしれません。そのような場合の判断に役立つよう、各スキルの設計根拠を詳しく解説しています。設計根拠を理解していれば、「このスキルを適用すべきか」という判断を、自信を持って行えるようになります。

### 他の手法との併用

Superpowersは、他のプロンプトエンジニアリング手法やカスタムインストラクションと併用できます。Superpowersが「行動のフレームワーク」を提供し、プロジェクト固有のインストラクション（CLAUDE.mdなど）が「具体的な規約」を提供する——このような役割分担は、非常に効果的です。

ただし、互いに矛盾する指示を含む複数のフレームワークを同時に適用すると、エージェントの振る舞いが不安定になる可能性があります。複数のフレームワークを併用する場合は、指示の整合性を確認してください。

- **LLMの仕組みや学習方法の詳細** — 本書はLLMの利用者向けであり、研究者向けではありません

## 本書の使い方——最大限に活用するために

最後に、本書を最大限に活用するための具体的なステップを提案します。

**ステップ1: 環境を準備する（所要時間: 30分）**

まず第2章に従って、お使いのプラットフォームにSuperpowersをインストールしてください。インストール自体は数分で完了しますが、動作確認まで含めて30分程度を見込んでください。

**ステップ2: 効果を体験する（所要時間: 1時間）**

お手元のプロジェクトで、小さな機能追加やバグ修正をSuperpowersを有効にした状態で行ってみてください。Superpowersなしの場合とエージェントの振る舞いがどう変わるかを観察します。特に、エージェントが以下の行動を取るかどうかに注目してください。

- 実装の前に要件を確認する質問を投げかけるか
- テストを先に書こうとするか
- 完了を宣言する前に検証コマンドを実行するか

**ステップ3: 理解を深める（所要時間: 2〜3時間）**

本書のパート1（第1章〜第3章）を通読し、Superpowersの設計思想と全体構造を理解してください。なぜそのように設計されているかを理解することで、スキルの効果を最大化できます。

特に第3章のコアワークフローは、パート2以降のすべての章の基盤となる重要な章です。ハードゲート、鉄の掟、合理化防止テーブルの3つの概念を確実に理解してから先に進んでください。

**ステップ4: スキルを個別に学ぶ（所要時間: 各20〜30分）**

パート2の各章を、必要に応じて読み進めてください。すべてを一度に読む必要はありません。実際の開発作業で必要になったスキルから順に学んでいくのが、最も効率的です。

推奨する学習順序は以下の通りです。

1. 第6章（テスト駆動開発）— 最も効果を実感しやすい
2. 第4章（ブレインストーミング）— ワークフローの起点
3. 第7章（デバッグ）— 日常的に使う機会が多い
4. 第5章（プランニング）— 中〜大規模タスクで威力を発揮
5. 第8章（コードレビュー）— チーム開発での品質向上
6. 第9章（Git操作）— ブランチ管理の効率化

**ステップ5: カスタマイズする（所要時間: 適宜）**

Superpowersの基本的な使い方に慣れたら、第10章を参考にして、プロジェクトやチームに合わせたカスタムスキルの作成に挑戦してください。自分のワークフローに最適化されたスキルは、汎用スキル以上の効果を発揮します。
